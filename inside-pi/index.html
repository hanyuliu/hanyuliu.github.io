#How the modules connect

The loop sits in the middle. The coding agent calls into it, and it calls out to the model through a function it's handed (streamFn). It never imports the coding agent, which is why it's easy to reuse.

Compaction lives in the coding agent, not in the loop. AgentSession checks the context size at fixed points, including the loop's prepareNextTurn hook, and asks the compaction module for a summary. The summary is saved in the session file, and the next request is rebuilt from it.

graph TD
    codingAgent[coding-agent: AgentSession] --> agentLoop[agent-loop]
    agentLoop -. "prepareNextTurn hook" .-> codingAgent
    codingAgent --> compaction
    compaction --> sessions[session file]
    compaction -. "summary request" .-> ai
    agentLoop -. "streamFn" .-> ai[pi-ai: about 40 LLM providers]
    agentLoop -. "tool.execute" .-> tools[tools: read, bash, edit, write]

#Glossary

Term Meaning
Turn One reply from the model, plus the tools it called and their results
Run Everything from one prompt until the loop stops; can be many turns
Tool call A request from the model to run a tool with some arguments
Hook An optional function in the config that the loop calls at a fixed point, so the host can watch or change what happens
Steering message Something the user typed during a run; added after the current turn's tools finish
Follow-up message Something that waits until the agent would otherwise stop
transcript. Prefix for helpers from pi-ai's packages/ai/src/utils/transcript.ts, which read and normalize the conversation
stopReason Why the model stopped: stop (done), toolUse (wants tools), length (ran out of tokens), error, or aborted
Context window The most tokens a model can read in one request
Compaction Replacing old messages with a model-written summary, saved as a compaction entry in the session file
reserveTokens Room kept free for the reply; Pi compacts when the context passes contextWindow - reserveTokens
keepRecentTokens How much of the newest context compaction keeps word for word
Session entry One line in the session file: a message, a compaction, a branch summary, a setting change, and so on. Each points to its parent, so entries form a tree
Projection The session entries as the model sees them: the latest compaction's summary, then the kept and newer entries
User-message span A user message and everything after it up to the next user message. The compaction code calls this a "turn" (isSplitTurn)
Split turn A cut that lands inside a user-message span; the start of the span gets its own summary
Branch summary A summary of the branch you leave when you move with /tree, saved as a branch_summary entry
sessionManager. Prefix for session-file functions in packages/coding-agent/src/core/session-manager.ts (no page yet)
Rules Promises a module keeps every time (MUST, MUST NOT, SHOULD)
Examples Concrete scenarios taken from Pi's own tests, written as Given / When / Then

  2. compaction. Start with "When compaction runs", then prepareCompaction and findProjectedCutPoint for where Pi cuts. Branch summaries are at the end.
