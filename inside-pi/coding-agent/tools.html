#Module: tools

The built-in tools of the coding agent: read, write, edit, and bash. They read and change files, run shell commands, cut long output down to a size the model can take, and keep two changes to the same file from running at once.

The loop page shows how a tool call runs from the loop's side: check the arguments, ask beforeToolCall, call execute, ask afterToolCall. This page is the other side: what happens inside execute.

Each tool is a factory that returns a ToolDefinition. The factory takes the working directory and options, and the definition holds a name, a description written for the model, a JSON schema for the arguments, and execute. The session wraps each definition into an AgentTool for the loop (wrapToolDefinition).

Every tool does its file or process work through a small *Operations object (ReadOperations, EditOperations, and so on). The default one uses the local disk and a local shell. Swap it and the same tool works over SSH or in a container.

Out of scope here: grep, find, ls, and powershell (same shape, less to say), and the renderers/ folder that draws tool calls in the terminal.

#Contracts

A tool definition. Only the fields the pseudocode uses are shown.

type ToolDefinition = {
    name: String,                         // "read", "write", "edit", "bash"
    description: String,                  // shown to the model with the schema
    parameters: JsonSchema,               // the arguments the model must send
    promptSnippet: String?,               // one line for the system prompt's tool list
    promptGuidelines: String[]?,          // rules for the system prompt
    prepareArguments: fn(Any) -> Any ?,   // fix common mistakes before the schema check
    executionMode: "sequential" | "parallel" ?,
    execute: async fn(toolCallId, params, signal?, onUpdate?, ctx?) -> AgentToolResult,
    // skipped: label, outputSchema, constrainedSampling, renderers
}

The arguments of each built-in tool.

read  { path: String, offset: Int?, limit: Int? }     // offset is 1-based
write { path: String, content: String }
edit  { path: String, edits: { oldText: String, newText: String }[] }
bash  { command: String, timeout: Int? }               // seconds; no timeout by default

Limits and the result of a cut. Whichever limit is hit first wins.

DEFAULT_MAX_LINES = 2000
DEFAULT_MAX_BYTES = 50 * 1024                         // 50KB

type TruncationResult = {
    content: String,                                  // what is kept
    truncated: Bool,
    truncatedBy: "lines" | "bytes" | null,
    totalLines: Int, outputLines: Int,
    firstLineExceedsLimit: Bool,                      // head cut only: line 1 alone is too big
    lastLinePartial: Bool,                            // tail cut only: end of one huge line
    // skipped: totalBytes, outputBytes, maxLines, maxBytes
}

Which tools are on. By default a session gets read, bash, edit, and write. grep, find, ls, and powershell exist but must be turned on.

#Behavior

#read

Sourceread.ts › createReadToolDefinition.execute anonymous

Reads a text file or an image. Text is cut from the head, and the note at the end tells the model which offset to use next.

async fn read.execute(id, {path, offset, limit}, signal, _, ctx)
    absolutePath = resolveReadPathAsync(path, ctx.cwd)
        // also tries macOS name variants, e.g. the narrow space in "Screenshot 10.42 AM.png"
    check the file is readable                         // → ops.access
    if the file is an image:                           // by its bytes, not its extension
        return [text note, image]                      // resized to fit the model
            // the note also says so if the model can't see images
    lines = the file as text, split on "\n"
    start = offset - 1, or 0
    if start >= number of lines:
        throw Error("Offset <offset> is beyond end of file (<n> lines total)")
    selected = lines from start, at most limit of them if limit is set
    cut = truncateHead(selected)
    if cut.firstLineExceedsLimit:
        return "[Line <n> is <size>, exceeds 50.0KB limit.
                 Use bash: sed -n '<n>p' <path> | head -c 51200]"
    if cut.truncated:
        return cut.content + "\n\n[Showing lines <a>-<b> of <total>. Use offset=<b+1> to continue.]"
            // when the byte limit was hit: "of <total> (50.0KB limit)"
    if limit stopped before the end of the file:
        return selected + "\n\n[<k> more lines in file. Use offset=<next> to continue.]"
    return selected

#truncateHead

Sourcetruncate.ts › truncateHead

Keeps the start. Used by read, where the start of a file is what you want. It never returns half a line.

fn truncateHead(content, {maxLines = 2000, maxBytes = 50KB}) -> TruncationResult
    lines = content split on "\n" (a trailing newline does not count as a line)
    if lines.count <= maxLines and bytes(content) <= maxBytes:
        return content, truncated = false
    if bytes(lines[0]) > maxBytes:
        return "", firstLineExceedsLimit = true
    kept = []
    for each line, from the first, while kept.count < maxLines:
        if bytes(kept) + bytes(line) + 1 > maxBytes:
            truncatedBy = "bytes"
            break
        kept.add(line)
    return kept joined by "\n", truncated = true, truncatedBy ("lines" if it stopped on count)

#truncateTail

Sourcetruncate.ts › truncateTail

Keeps the end. Used by bash, where errors and final results come last.

fn truncateTail(content, {maxLines = 2000, maxBytes = 50KB}) -> TruncationResult
    if content fits both limits:
        return content, truncated = false
    kept = []
    for each line, from the last, while kept.count < maxLines:
        if bytes(kept) + bytes(line) + 1 > maxBytes:
            if kept is empty:
                kept = [the last maxBytes of this line]   // cut on a UTF-8 character boundary
                lastLinePartial = true
            break
        put line at the front of kept
    return kept joined by "\n", truncated = true

#write

Sourcewrite.ts › createWriteToolDefinition.execute anonymous

Creates or replaces a whole file. Parent folders are created as needed.

async fn write.execute(id, {path, content}, signal, _, ctx)
    absolutePath = resolveToCwd(path, ctx.cwd)          // also expands ~ and strips a leading @
    return withFileMutationQueue(absolutePath, fn():
        throw if aborted
        create the parent folders                       // → ops.mkdir
        throw if aborted
        write content to the file                       // → ops.writeFile
        throw if aborted
        return "Successfully wrote to <path>")
    // why: check the signal after each step instead of rejecting from an abort listener.
    //      Rejecting early would free the queue while a write is still in flight.

#withFileMutationQueue

Sourcefile-mutation-queue.ts › withFileMutationQueue › getMutationQueueKey

Tools run in parallel by default, so two edit calls on one file could both read the old content, and the second write would erase the first. This queue makes changes to the same file wait for each other. Changes to different files still run at the same time.

async fn withFileMutationQueue(filePath, fn)
    key = realpath(filePath), or the resolved path if the file does not exist yet
        // why: a symlink and its target are one file, so they share one queue
    previous = fileMutationQueues[key] or done
    mine = a promise that resolves when fn finishes
    fileMutationQueues[key] = previous, then mine
        // note: registrations go through one global chain, so two calls can't both
        //       read the old queue before either one adds itself
    await previous
    try:
        return fn()
    finally:
        resolve mine                                    // the next change to this file starts
        if fileMutationQueues[key] is still this chain: remove it

#edit

Sourceedit.ts › createEditToolDefinition.execute anonymous › validateEditInput

Changes a file by exact text replacement. There are no line numbers and no patches: the model sends the old text and the new text. The file keeps its line endings and byte-order mark.

async fn edit.execute(id, input, signal, _, ctx)
    if input.edits is empty:
        throw Error("Edit tool input is invalid. edits must contain at least one replacement.")
    absolutePath = resolveToCwd(input.path, ctx.cwd)
    return withFileMutationQueue(absolutePath, fn():
        if the file can't be read and written:
            throw Error("Could not edit file: <path>. Error code: <code>.")
        raw = the file as text
        bom, text = split off a UTF-8 byte-order mark
            // why: the model never types an invisible BOM
        ending = "\r\n" if the first line ends that way, else "\n"
        text = text with every line ending as "\n"
        before, after = applyEditsToNormalizedContent(text, input.edits, path)
        write bom + after with ending restored
        return "Successfully replaced <n> block(s) in <path>.",
               details: { diff, patch, firstChangedLine }   // for the terminal, not the model
    )

#applyEditsToNormalizedContent

Sourceedit-diff.ts › applyEditsToNormalizedContent › fuzzyFindText

Finds every oldText in the original file, checks them all, and only then replaces. One bad edit means no edit is written.

fn applyEditsToNormalizedContent(content, edits, path) -> { baseContent, newContent }
    for each edit: if oldText is empty: throw "oldText must not be empty in <path>."
    usesFuzzy = any oldText is not found as-is, but is found after normalizeForFuzzyMatch
    base = normalizeForFuzzyMatch(content) if usesFuzzy else content
    matches = []
    for each edit, i:
        find oldText in base                            // exact first, then normalized
        if not found:
            throw "Could not find edits[i] in <path>. The oldText must match exactly
                   including all whitespace and newlines."
        if it occurs more than once:
            throw "Found <k> occurrences of edits[i] in <path>. Each oldText must be unique. ..."
        matches.add(i, where, length, newText)
    sort matches by position
    if two matches overlap:
        throw "edits[a] and edits[b] overlap in <path>. Merge them into one edit or ..."
    if usesFuzzy:
        newContent = rewrite only the lines the matches touch; copy every other line
                     from content unchanged    // → applyReplacementsPreservingUnchangedLines
    else:
        newContent = replace the matches, last one first // why: earlier offsets stay valid
    if newContent == content:
        throw "No changes made to <path>. ..."
    return { baseContent: content, newContent }

normalizeForFuzzyMatch strips spaces at the end of each line, and turns smart quotes, Unicode dashes, and special spaces into their plain ASCII forms. The messages above are for a call with several edits. With one edit, they say "the text" instead of "edits[i]".

#prepareEditArguments

fn prepareEditArguments(input) -> EditToolInput
    if input.edits is a JSON string:
        input.edits = the parsed array (or [the parsed object])
        // note: from the code: "Some models (Opus 4.6, GLM-5.1) send edits as a JSON string"

#bash

Sourcebash.ts › createShellToolDefinition.execute anonymous

Runs a command and returns its combined stdout and stderr, cut from the tail. While it runs, the terminal gets the latest output at most every 100ms.

async fn bash.execute(id, {command, timeout}, signal, onUpdate, ctx)
    command = commandPrefix + "\n" + command, if a prefix is set
    env = the shell environment, plus PI_SESSION_ID, PI_SESSION_FILE, PI_PROVIDER,
          PI_MODEL, PI_REASONING_LEVEL       // unless exposeSessionEnvironment is false
    apply spawnHook?(command, cwd, env)                 // an extension may change all three
    output = new OutputAccumulator(tempFilePrefix "pi-bash")
    try:
        exitCode = ops.exec(command, cwd, onData = output.append, signal, timeout, env)
    catch "aborted":
        throw Error(<output so far> + "\n\nCommand aborted")
    catch "timeout:<s>":
        throw Error(<output so far> + "\n\nCommand timed out after <s> seconds")
    if exitCode is null:                                // only from custom ops
        throw Error(<output> + "\n\nCommand terminated without an exit code")
    snapshot = output.snapshot()                        // truncateTail of what it kept
    text = snapshot.content or "(no output)"
    if snapshot was cut:
        text += "\n\n[Showing lines <a>-<b> of <total>. Full output: <temp file>]"
    if exitCode is not 0:
        return text + "\n\nCommand exited with code <exitCode>", isError = true
    return text

#createLocalShellOperations

Sourcebash.ts › createLocalShellOperations

The default exec: starts the shell and stops it on abort or timeout.

async fn exec(command, cwd, {onData, signal, timeout, env}) -> { exitCode }
    if cwd does not exist:
        throw Error("Working directory does not exist: <cwd>\nCannot execute bash commands.")
    child = spawn the shell with command, in its own process group
    send child's stdout and stderr to onData
    on timeout or abort: killProcessTree(child)    // the shell and every process it started
    exitCode = wait for the child
    if aborted: throw "aborted"
    if timed out: throw "timeout:<timeout>"
    return exitCode, or 128 + signal number if a signal killed the shell

#OutputAccumulator

Sourceoutput-accumulator.ts › OutputAccumulator.append › OutputAccumulator.snapshot

Collects command output with bounded memory. It keeps only the recent tail in memory. Once the output passes either limit, it also writes everything to a temp file, so the model can read the full output later.

class OutputAccumulator
    fn append(chunk)
        decode chunk as UTF-8, keeping a character split across chunks for the next one
        add the text to tail
        if tail passes 200KB: keep only its last 100KB          // memory stays bounded
        count lines and bytes
        if the output is over 2,000 lines or 50KB:
            open the temp file if needed: $TMPDIR/pi-bash-<random>.log, readable only by you
            write the chunk to it (earlier chunks are copied in when the file opens)
        else:
            keep the chunk in memory
    fn snapshot() -> { content, truncation, fullOutputPath }
        truncation = truncateTail(tail), with the totals of the whole output
        return truncation.content, truncation, the temp file path if there is one

#NestedToolCallRunner.execute

Sourcenested-tool-calls.ts › NestedToolCallRunner.execute

Some tools call other tools while they run, through ctx.executeTool(). The codemode tool does this for model-written scripts. The loop never sees these calls. The session runs each one through the loop's own tool pipeline, so beforeToolCall and afterToolCall still apply.

async fn execute(callerId, name, args, options) -> AgentToolCallOutcome
    scope = scopes[callerId], or a new one with its own NestedCallRecorder
    toolCall = { id: callerId + "/" + scope.nextId, name, arguments: args }
        // ids "call_7/1", "call_7/2", ... below the caller "call_7"
    record = scope.recorder.start(toolCall)
    emit tool_execution_start{..., parentToolCallId: callerId}
    if the agent runs tools sequentially, or the tool's executionMode is "sequential":
        wait for the earlier exclusive nested call to finish
    outcome = host.runToolCall(toolCall, ...)    // → agentLoop.runToolCall, with the session's hooks
    scope.recorder.finish(record, outcome.isError, its text)
    add outcome.result.usage to the recorder
    emit tool_execution_end{..., parentToolCallId: callerId}
    return outcome                                      // a failed tool is isError, never a throw

When the caller's result message starts, the session takes the record (takeRecord) and stores it on that message as nestedCalls, and adds the nested usage to the message's usage. The record keeps at most 256 calls and 32KB of arguments. Larger arguments are left out and the record is marked incomplete.

#Rules

MUST     cut text output at 2,000 lines or 50KB, whichever comes first
MUST     keep the start of a file (read) and the end of command output (bash)
MUST     end a cut result with a note that tells the model how to get the rest
MUST NOT return half a line from read          // a huge first line gets a sed hint instead
MUST     save the full bash output to a temp file once it passes either limit
MUST     run write and edit on the same real file one at a time, in the order they were called
MUST     let changes to different files run at the same time
MUST NOT free a file's queue while a write to it may still be in flight, even after an abort
MUST     match every edits[].oldText against the original file, not after earlier edits
MUST     reject an edit whose oldText is empty, missing, not unique, or overlaps another
MUST NOT write any part of an edit call when one of its edits fails
MUST     keep the file's line endings and byte-order mark through an edit
SHOULD   try an exact match before a normalized (fuzzy) match
MUST     report a non-zero exit code as an error result that still carries the output
MUST     kill the whole process tree on abort or timeout
MUST     run nested tool calls through beforeToolCall and afterToolCall
MUST     run nested calls to sequential tools one at a time

#Notes

Tool descriptions are written for the model, and they say what the code does: read's description tells the model about the 2,000-line and 50KB limits and to "continue with offset until complete". The promptSnippet and promptGuidelines fields go into the system prompt, for example edit's "Keep edits[].oldText as small as possible while still being unique in the file."

A tool throws to report a failure. The loop turns the throw into an error result, so the model reads the message and can try again. bash is the exception: a non-zero exit returns a normal result marked isError, so the output is kept with it.

edit builds a diff and a unified patch only after it writes. The terminal shows the diff. The model gets one line: "Successfully replaced 1 block(s) in ."
