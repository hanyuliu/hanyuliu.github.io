#Module: compaction

Keeps a long session inside the model's context window. Old messages are replaced by a summary that the model writes, and the newest messages are kept as they are.

A model can only read so many tokens at once. When a session gets close to that limit, Pi asks the model to summarize the older part of the conversation, saves the summary in the session file, and from then on sends the summary in place of those messages.

This page covers three parts:

  • When compaction runs. That logic lives in AgentSession, the class in the coding agent that drives the agent loop.
  • How it plans and writes a summary. That is the compaction/ folder.
  • Branch summaries, a close cousin: when you jump to another branch of the session tree, Pi can summarize the branch you're leaving.

One word needs care. In the loop, a turn is one reply from the model. In the compaction code, a "turn" means a user-message span: a user message and every reply and tool result after it, up to the next user message. Names like isSplitTurn and turnStartIndex use that second meaning.

#Contracts

Settings. These come from settings.json, and a model can override the two token values (compaction.modelOverrides).

type CompactionSettings = {
    enabled: Bool,                 // default true
    reserveTokens: Int,            // room kept free for the reply; default 16384
    keepRecentTokens: Int,         // newest context to keep word for word; default 20000
}

The plan. prepareCompaction works out what to summarize and what to keep, without calling the model.

type CompactionPreparation = {
    firstKeptEntryId: String,              // first session entry kept as is
    messagesToSummarize: AgentMessage[],   // older history, goes into the main summary
    turnPrefixMessages: AgentMessage[],    // start of a split user-message span, if any
    isSplitTurn: Bool,
    tokensBefore: Int,                     // estimated context size before compaction
    previousSummary: String?,              // the last compaction's summary, updated in place
    fileOps: FileOperations,               // files read, written, and edited so far
    settings: CompactionSettings,
}

type FileOperations = { read: Set<String>, written: Set<String>, edited: Set<String> }

The result, and how it is saved. A compaction is an entry in the session tree, like a message.

type CompactionResult = {
    summary: String,
    firstKeptEntryId: String,
    tokensBefore: Int,
    usage: Usage?,                 // tokens spent writing the summary
    details: Any?,                 // Pi's own summaries store { readFiles, modifiedFiles }
}

type CompactionEntry = SessionEntry & {
    type: "compaction",
    summary: String,
    firstKeptEntryId: String,      // its own id when nothing is kept
    tokensBefore: Int,
    fromHook: Bool?,               // true when an extension wrote the summary
    systemMessage: SystemMessage?, // the system message at the time, replayed after compaction
    // skipped: details, usage
}

type BranchSummaryEntry = SessionEntry & {
    type: "branch_summary",
    summary: String,
    fromId: String,                // the entry we navigated away from
    // skipped: details, usage, fromHook
}

#Behavior

#When compaction runs

There are four ways in:

Path When Can retry the turn?
Between turns after a turn's tool results are saved, before the next request in the same run no
After a run the low-level loop has ended; checks the last reply yes, once, after an overflow
Before a prompt the user sends a new message no
Manual /compact [instructions], RPC, or an extension no

The first three are automatic and use the same threshold. The manual path skips the threshold and always tries.

#_compactBeforeNextAssistantResponse

Sourceagent-session.ts › AgentSession._compactBeforeNextAssistantResponse › AgentSession._exceedsCompactionThreshold

AgentSession installs this on the loop's prepareNextTurn hook, so it runs at the top of every turn after the first. A long tool result can push the context over the limit in the middle of a run, and this is where Pi catches it. It also rebuilds the context from the session file, so the next request always matches what is saved.

async fn _compactBeforeNextAssistantResponse(context) -> AgentContext
    projection = sessionManager.buildSessionProjection()
    if there is no model, or the model is virtual, or not _exceedsCompactionThreshold(model, projection):
        return context with messages = projection.messages
    _runAutoCompaction("threshold", willRetry = false)
    return context with messages = sessionManager.buildSessionProjection().messages

fn _exceedsCompactionThreshold(model, projection) -> Bool
    if model.contextWindow <= 0:
        return false
    tokens = estimateProjectedContextTokens(projection, sessionManager.getBranch()).tokens
    return shouldCompact(tokens, model.contextWindow, settings for this model)

A virtual model (one that routes each request to a real model) is checked later, in prepareRequest, against the model the request is routed to.

The loop only calls prepareNextTurn when another request follows. So when a tool batch ends the run (every result has terminate), this check does not run.

#shouldCompact

Sourcecompaction.ts › shouldCompact

The threshold itself.

fn shouldCompact(contextTokens, contextWindow, settings) -> Bool
    if not settings.enabled:
        return false
    return contextTokens > contextWindow - settings.reserveTokens

#estimateProjectedContextTokens

Sourcecompaction.ts › estimateProjectedContextTokens › estimateContextTokens › estimateTokens

Pi needs the size of the context before it sends it. The best number is the token count the provider reported for the last reply. Messages added after that reply are estimated at 4 characters per token.

fn estimateProjectedContextTokens(projection, branchEntries) -> ContextUsageEstimate
    estimate = estimateContextTokens(projection.messages)
        // the last reply's reported usage, plus estimateTokens() for each later message
    if that usage came from an entry after the latest context_edit or compaction entry:
        return estimate
    // why: usage reported before an edit or a compaction describes a context that no longer exists
    return the sum of estimateTokens() over the current system message and every non-system message

fn estimateTokens(message) -> Int
    count the characters of its text, thinking, tool call names and arguments, and summaries
    count each image as 4800 characters
    return ceil(characters / 4)       // rounds up on purpose, so it errs on the high side

#_checkCompaction

Sourceagent-session.ts › AgentSession._checkCompaction

Runs after the low-level loop ends (from _handlePostAgentRun), and before a new prompt starts (from _prepareRun, with skipAbortedCheck = false). It looks at the last reply and decides between overflow recovery and the ordinary threshold. It returns whether the session should call agent.continue().

async fn _checkCompaction(assistantMessage, skipAbortedCheck = true, toolResults = []) -> Bool
    settings = settingsManager.getCompactionSettings(model)
    if not settings.enabled:
        return false
    if skipAbortedCheck and assistantMessage.stopReason is "aborted":
        return false
    if assistantMessage is older than the latest compaction entry:
        return false
        // why: its usage or error describes the context before that compaction
    sameModel = assistantMessage came from the current model
        // why: an overflow from a smaller model must not compact for a larger one
    contextOverflow = sameModel and (the reply is a context-overflow error,
                      or its reported usage fills the context window)
    recoverableLength = sameModel and isRecoverableLength(assistantMessage, model.maxTokens)
        // stopped at "length" before reaching the model's own output limit
    if contextOverflow or recoverableLength:
        willRetry = assistantMessage.stopReason is not "stop"
        if not willRetry:
            return _runAutoCompaction("overflow", false)   // the answer is complete: keep it
        if _overflowRecoveryAttempted:
            emit compaction_end{errorMessage: "... recovery failed after one compact-and-retry attempt ..."}
            return false
        _overflowRecoveryAttempted = true
        _omitRecoveryAttempt(assistantMessage, toolResults)
            // saves context_edit entries that hide the failed attempt from the model
        return _runAutoCompaction("overflow", willRetry = true)
    contextTokens = the reply's reported usage, or an estimate when it has none
        // (error replies, zero usage, and context edits use the estimate;
        //  if the estimate leans on usage from before the latest compaction: return false)
    if shouldCompact(contextTokens, contextWindow, settings):
        return _runAutoCompaction("threshold", false)
    return false

_overflowRecoveryAttempted goes back to false when a user message starts, or when a reply ends without "error" or "length".

#_runAutoCompaction

Sourceagent-session.ts › AgentSession._runAutoCompaction › AgentSession._runDefaultCompaction

Runs one automatic compaction from plan to saved entry.

async fn _runAutoCompaction(reason, willRetry) -> Bool
    preparation = prepareCompaction(sessionManager.getBranch(), settings)
    if no preparation:
        return false
    emit compaction_start{reason}
    try:
        result = @hook session_before_compact{preparation, reason, willRetry}
        if result.cancel:
            throw Error("Compaction cancelled")
        compaction = result.compaction or _runDefaultCompaction(preparation, model, ...)
            // _runDefaultCompaction resolves the model's auth, then calls compact()
        sessionManager.appendCompaction(summary, firstKeptEntryId, tokensBefore,
            details, fromHook, usage)
        rebuild the agent's messages from the session file
        emit session_compact, then compaction_end{result}
        if willRetry:
            return true                 // run the failed turn again, once
        return agent.hasQueuedMessages()
        // why: messages may have queued up while compacting; continue once to deliver them
    catch e:
        emit compaction_end{aborted or errorMessage}, then session_compact_failed
        return false

#prepareCompaction

Sourcecompaction.ts › prepareCompaction

Plans a compaction without calling the model. It works on the projection: the session entries as the model currently sees them, with the latest compaction already applied.

fn prepareCompaction(pathEntries, settings) -> CompactionPreparation?
    if the last entry is a compaction:
        return none                                  // nothing new since then
    projection = sessionManager.buildSessionProjection(pathEntries)
    previous = the projected compaction entry, if any (it always comes first)
    start = the index after previous, or 0
        // note: this range starts with the messages the previous compaction kept,
        //       so they get summarized once the recent window moves past them
    tokensBefore = estimateProjectedContextTokens(projection, pathEntries).tokens
    cut = findProjectedCutPoint(projection.entries, start, end, settings.keepRecentTokens)
    historyEnd = cut.turnStartIndex if cut.isSplitTurn, else cut.firstKeptEntryIndex
    messagesToSummarize = messages of entries [start, historyEnd), without system messages
    turnPrefixMessages = messages of entries [cut.turnStartIndex, cut.firstKeptEntryIndex)
                         if cut.isSplitTurn, else []
    if both lists are empty:
        return none                                  // everything still fits
    fileOps = files from previous.details (only if Pi wrote it, fromHook false)
              + extractFileOpsFromMessage() for every message in both lists
    return { firstKeptEntryId, messagesToSummarize, turnPrefixMessages, cut.isSplitTurn,
             tokensBefore, previousSummary = previous.summary, fileOps, settings }

#findProjectedCutPoint

Sourcecompaction.ts › findProjectedCutPoint › findCutPoint

Decides where the kept part starts. It walks back from the newest entry until it has keepRecentTokens worth, then cuts at the nearest entry where a cut is allowed. findCutPoint is the same walk over raw session entries; compaction uses the projected version.

fn findProjectedCutPoint(entries, start, end, keepRecentTokens) -> CutPointResult
    cutPoints = indices of entries with a user, assistant, bashExecution, custom,
                or summary message
        // never a tool result: it must stay right after the tool call that asked for it
    if cutPoints is empty:
        return { firstKeptEntryIndex: start, turnStartIndex: -1, isSplitTurn: false }
    cut = cutPoints[0]                               // default: keep everything
    walk back from entries[end - 1], adding estimateTokens() of each entry:
        once the total reaches keepRecentTokens at entry i:
            cut = the first cut point at or after i, or else the last cut point
            // why: if trailing tool results alone pass the budget, keep the tool call
            //      that made them instead of falling back to the first message (#9740)
            stop
    if everything after cut is an omitted failed attempt (from overflow recovery):
        cut moves one entry later
    move cut back over earlier entries that add nothing to the context (labels, settings)
    startsTurn = entries[cut] has a user, bashExecution, custom, or summary message
    turnStart = -1 if startsTurn, else the nearest earlier entry that starts a span
    return { firstKeptEntryIndex: cut, turnStartIndex: turnStart,
             isSplitTurn: not startsTurn and turnStart != -1 }

When one user-message span is bigger than keepRecentTokens, the cut lands on an assistant message inside it. That is a split turn: the start of the span gets its own summary, so the kept half still makes sense.

#compact

Sourcecompaction.ts › compact

Writes the summary. For a split turn it makes two model calls, one after the other, and joins the results.

async fn compact(preparation, model, apiKey, ..., customInstructions?) -> CompactionResult
    if preparation.isSplitTurn and turnPrefixMessages is not empty:
        history = previousSummary or "No prior history."
        if messagesToSummarize is not empty:
            history = generateSummaryWithUsage(messagesToSummarize, ..., previousSummary)
        prefix = generateTurnPrefixSummary(turnPrefixMessages, ...)
        summary = history + "\n\n---\n\n**Turn Context (split turn):**\n\n" + prefix
    else:
        summary = generateSummaryWithUsage(messagesToSummarize, ..., previousSummary)
    readFiles, modifiedFiles = computeFileLists(fileOps)
    summary += formatFileOperations(readFiles, modifiedFiles)
    return { summary, firstKeptEntryId, tokensBefore, usage of both calls,
             details: { readFiles, modifiedFiles } }

#generateSummaryWithUsage

Sourcecompaction.ts › generateSummaryWithUsage › generateTurnPrefixSummary › completeSummarization

One summary request. The conversation goes in as plain text inside a single user message, not as a chat history.

async fn generateSummaryWithUsage(messages, model, reserveTokens, ..., customInstructions?, previousSummary?)
        -> { text, usage }
    maxTokens = min(0.8 * reserveTokens, model.maxTokens)
    prompt = UPDATE_SUMMARIZATION_PROMPT if previousSummary, else SUMMARIZATION_PROMPT
    if customInstructions:
        prompt += "\n\nAdditional focus: " + customInstructions
    text = "<conversation>" + serializeConversation(convertToLlm(messages)) + "</conversation>"
    if previousSummary:
        text += "<previous-summary>" + previousSummary + "</previous-summary>"
    response = completeSummarization(model, system: SUMMARIZATION_SYSTEM_PROMPT,
                                     user: text + prompt, maxTokens)
        // cacheRetention "none"     why: a one-off prompt is not worth a cache write
        // retried on dropped streams with the session's retry policy
    if response.stopReason is "error" or "length":
        throw Error(...)        // why: a cut-off summary must never become a checkpoint
    if response has a tool call:
        throw Error("Summarization attempted to call a tool")
    return text of response, response.usage

generateTurnPrefixSummary is the same call with a smaller output cap (0.5 * reserveTokens) and TURN_PREFIX_SUMMARIZATION_PROMPT, which asks for three sections: Original Request, Progress So Far, and Context Needed to Continue.

The main prompt asks for a fixed format: Goal, Constraints & Preferences, Progress (Done, In Progress, Blocked), Key Decisions, Next Steps, and Critical Context. The update prompt asks the model to keep everything from the previous summary, add what is new, and move finished items from In Progress to Done.

#serializeConversation

Sourceutils.ts › serializeConversation › extractFileOpsFromMessage › computeFileLists

Turns messages into the text the summarizer reads, and collects file paths from tool calls along the way.

fn serializeConversation(messages) -> String
    for each message:
        match message.role:
            "user":        "[User]: " + text
            "assistant":   "[Assistant]: " + text
                           "[Assistant tool calls]: read(path=\"a.ts\"); edit(path=\"b.ts\", ...)"
            "toolResult":  "[Tool result]: " + the first 2000 characters,
                           then "[... N more characters truncated]"
        // thinking is left out
        // why: replayed thinking is often not in the model's live context, and it can make
        //      the request bigger than the context it summarizes
    join with blank lines

fn extractFileOpsFromMessage(message, fileOps)
    for each read, write, or edit tool call with a path argument:
        add the path to fileOps.read, .written, or .edited
    // also the calls a codemode script made, recorded as nestedCalls on its tool result

fn computeFileLists(fileOps) -> { readFiles, modifiedFiles }
    modifiedFiles = edited + written, sorted
    readFiles = read minus modifiedFiles, sorted

#buildContextEntries

Sourcesession-manager.ts › buildContextEntries › SessionManager.appendCompaction

Nothing is deleted from the session file. A compaction is a new entry at the end of the branch, and the projection decides what the model sees.

fn buildContextEntries(entries, leafId) -> SessionEntry[]
    path = the entries from the root to leafId
    compaction = the last compaction entry on path
    if no compaction:
        return path
    result = [compaction]                    // turns into the summary message
    add the path entries from compaction.firstKeptEntryId up to the compaction,
        skipping system messages
    add every entry after the compaction
    return result

The compaction entry projects to two messages: the system message saved on it, then a compactionSummary message. convertToLlm sends the summary to the model as a user message: "The conversation history before this point was compacted into the following summary:

... ".

#navigateTree

Sourceagent-session.ts › AgentSession.navigateTree

/tree moves to another point in the session tree. If the user asks for it, Pi first summarizes the branch being left, and attaches that summary at the new position.

async fn navigateTree(targetId, options) -> { editorText?, cancelled, summaryEntry? }
    if a response is streaming or a compaction is running:
        throw Error("Wait for ...")
    entries, commonAncestorId = collectEntriesForBranchSummary(sessionManager, oldLeafId, targetId)
    result = @hook session_before_tree{preparation}
    if result.cancel:
        return { cancelled: true }
    if options.summarize and entries is not empty:
        summary = result.summary or generateBranchSummary(entries, ...)
    newLeaf = the target's parent if the target is a user message (its text goes back
              into the editor), else the target
    if summary:
        sessionManager.branchWithSummary(newLeaf, summary, ...)   // a branch_summary entry
    else:
        sessionManager.branch(newLeaf)

#collectEntriesForBranchSummary

Sourcebranch-summarization.ts › collectEntriesForBranchSummary
fn collectEntriesForBranchSummary(session, oldLeafId, targetId) -> { entries, commonAncestorId }
    if no oldLeafId:
        return { entries: [], commonAncestorId: null }
    commonAncestorId = the deepest entry on both the old path and the target path
    entries = walk parent links from oldLeafId up to commonAncestorId (not included),
              then reverse, oldest first
        // note: does not stop at compaction entries; their summaries become input too

#prepareBranchEntries

Sourcebranch-summarization.ts › prepareBranchEntries

Fits the abandoned branch into a token budget, keeping the newest part.

fn prepareBranchEntries(entries, tokenBudget) -> BranchPreparation
    fileOps = the file lists of Pi-written branch_summary entries in entries
    walk entries from newest to oldest:
        message = the entry as a message (tool results are skipped; compaction and
                  branch_summary entries become summary messages)
        add its file operations to fileOps
        if tokenBudget > 0 and adding message would pass tokenBudget:
            if it is a compaction or branch summary and the total is under 90% of tokenBudget:
                keep it anyway           // why: (code comment) a summary is important context
            stop
        keep message
    return { kept messages oldest first, fileOps, totalTokens }

#generateBranchSummary

Sourcebranch-summarization.ts › generateBranchSummary
async fn generateBranchSummary(entries, options) -> BranchSummaryResult
    tokenBudget = (model.contextWindow or 128000) - (options.reserveTokens or 16384)
    messages, fileOps = prepareBranchEntries(entries, tokenBudget)
    if messages is empty:
        return { summary: "No content to summarize" }
    instructions = BRANCH_SUMMARY_PROMPT, with options.customInstructions appended,
                   or replaced by them when options.replaceInstructions
    response = completeSummarization(..., maxTokens = min(4096, model.maxTokens))
    if response was aborted:
        return { aborted: true }
    if response stopped at "error" or "length", or has a tool call:
        return { error }
    summary = BRANCH_SUMMARY_PREAMBLE + text + formatFileOperations(computeFileLists(fileOps))
    return { summary, usage, readFiles, modifiedFiles }

The branch format is the compaction format without Critical Context. The preamble tells the model: "The user explored a different conversation branch before returning here."

#Rules

MUST     compact automatically only when contextTokens > contextWindow - reserveTokens
MUST     check the threshold between turns, after a run, and before a new prompt
MUST NOT check between turns after a tool batch that ends the run
MUST NOT cut at a tool result
         // why: a tool result must stay right after the tool call that asked for it
MUST     keep the newest messages, about keepRecentTokens worth, as they are
MUST     summarize the start of a split user-message span separately, and append it
         to the history summary
MUST     pass the previous summary to the next compaction, and ask the model to update it
MUST NOT compact again when the last entry is already a compaction
MUST     send the conversation to the summarizer as text, not as chat messages
         // why: so the model does not try to continue the conversation
MUST     cut each tool result to 2000 characters in the summarizer's input
MUST NOT include thinking in the summarizer's input
MUST NOT save a summary whose reply stopped at "error" or "length", or that calls a tool
MUST NOT write to the prompt cache for summary requests
MUST     carry file lists forward only from summaries Pi wrote (fromHook is not true)
MUST     let session_before_compact cancel a compaction or supply the summary
MUST     retry a turn that overflowed or was cut off at most once, until a user message
         starts or a reply succeeds
MUST NOT retry a reply that finished normally (stopReason "stop"); compact only
MUST     ignore replies that are older than the latest compaction
MUST NOT delete entries from the session file; a compaction only adds an entry

#Notes

Most of the size of a session comes from tool results, especially read and bash. That is why the summarizer sees only the first 2000 characters of each one: it needs to know what happened, not every line of output.

Summaries build on each other. Each compaction passes the previous summary to the model and asks it to update it, rather than starting over. The file lists work the same way: each compaction starts from the lists saved on the previous one and adds the new paths.

Extensions can replace Pi's summarizer entirely. A session_before_compact handler can return its own summary and firstKeptEntryId, for example to use a cheaper model. Pi then saves it with fromHook: true and does not carry file lists from it.

Compaction does not change the agent loop. The loop only sees a prepareNextTurn hook that returns a new context, and a shorter conversation on the next request.
