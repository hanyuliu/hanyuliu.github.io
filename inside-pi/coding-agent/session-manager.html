#Module: session-manager

Saves each session as a JSONL file whose entries form a tree, and rebuilds the conversation the model sees from one branch of that tree.

Every message, tool result, model change, compaction, and summary becomes one entry: one JSON object on one line of the session file. Each entry has an id and a parentId, so the entries form a tree. The leaf is the entry the session is at right now. A new entry is always a child of the leaf, and then becomes the new leaf. Going back to an earlier point only moves the leaf, so the next entry starts a new branch and the old branch stays in the file.

The file only grows. Pi never changes or deletes a line it wrote. To change what the model sees, it adds an entry instead: a compaction, a branch summary, or a context edit. Before every request, the projection walks the active branch from the root to the leaf and turns its entries into messages.

This page also covers the two places outside session-manager.ts that matter most for the file: where AgentSession saves each message, and how /fork and /clone start a new file from part of an old one.

Out of scope here: the session picker (list, listAll, buildSessionInfo), export and share, and what goes into the system message (a later post).

#Contracts

The first line of every file is a header. It is not part of the tree.

CURRENT_SESSION_VERSION = 3

type SessionHeader = {
    type: "session",
    version: Int?,                  // missing in version 1 files
    id: String,                     // a UUIDv7 by default, or --session-id
    timestamp: String,              // ISO 8601
    cwd: String,                    // the folder Pi was started in
    parentSession: String?,         // path of the file this one was forked or cloned from
}

Every other line is an entry. All entries share four fields.

type SessionEntryBase = {

}

The entry types. Only the fields the pseudocode uses are shown.

type SessionEntry =
    SessionMessageEntry      { type: "message", message: AgentMessage }   // system, user, assistant, toolResult, bashExecution
  | ModelChangeEntry         { type: "model_change", provider, modelId }
  | ThinkingLevelChangeEntry { type: "thinking_level_change", thinkingLevel }
  | CompactionEntry          { type: "compaction", summary, firstKeptEntryId, tokensBefore,

  | BranchSummaryEntry       { type: "branch_summary", fromId, summary, details?, usage?, fromHook? }
  | CustomMessageEntry       { type: "custom_message", customType, content, display, details? }
  | ContextEditEntry         { type: "context_edit", targetId, replacement: { content } | null }
  | CustomEntry              { type: "custom", customType, data? }       // extension state, never sent

#Saving a message

Sourceagent-session.ts › AgentSession._handleAgentEvent

AgentSession subscribes to the Agent's events. When a message is complete, it saves it as an entry. This runs after extensions and the UI have seen the event.

on message_end(message):
    match message.role:
        "custom":
            entryId = sessionManager.appendCustomMessageEntry(message.customType,
                          message.content, message.display, message.details)
        "system", "user", "assistant", "toolResult":
            entryId = sessionManager.appendMessage(message)
        otherwise:
            nothing        // bashExecution, compactionSummary, branchSummary are saved elsewhere
    remember entryId for this message

A streaming reply is saved once, when it ends. Its partial text is never written to the file. The other entries come from other places: /model adds a model_change, compaction adds a compaction, !command adds a bashExecution message, and so on.

#_appendEntry

Sourcesession-manager.ts › SessionManager._appendEntry

Adds the entry in memory, moves the leaf to it, and saves it.

fn _appendEntry(entry)

    byId[entry.id] = entry

    _persist(entry)

#_persist

Sourcesession-manager.ts › SessionManager._persist › SessionManager._hasConversation

Writes one entry to the file. The file is created late: only once the session has a user or assistant message.

fn _persist(entry)
    if not persist or no sessionFile:
        return                                  // an in-memory session
    if not flushed:
        if no entry is a user or assistant message:
            return
            // why: opening and closing pi without chatting leaves no file behind
        open sessionFile with flag "wx"         // fails if the file already exists
        write every entry in fileEntries, header first, as one JSON line each
        flushed = true
    else:
        append JSON(entry) + "\n" to sessionFile

The file starts at the first user message, not the first reply. The code says why: it "keeps the prompt on disk if the first turn never completes (#10000)".

#newSession

Sourcesession-manager.ts › SessionManager.newSession › createSessionId

Starts an empty session in memory. Nothing is written yet (see _persist).

fn newSession(options?) -> String?
    if options.id is set: assertValidSessionId(options.id)
    sessionId = options.id or uuidv7()
    header = { type: "session", version: CURRENT_SESSION_VERSION, id: sessionId,
               timestamp: now, cwd, parentSession: options.parentSession }
    fileEntries = [header]
    clear byId and the labels
    leafId = null
    flushed = false
    if persist:
        sessionFile = sessionDir + "/" + <timestamp with ":" and "." as "-"> + "_" + sessionId + ".jsonl"
    return sessionFile

A file name looks like 2026-11-21T09-30-00-000Z_019a....jsonl. A UUIDv7 starts with the time, so session ids sort by creation time too.

#open

Sourcesession-manager.ts › SessionManager.open › SessionManager._setSessionFile

Opens a file by path. The header gives the session's working directory.

static fn open(path, sessionDir?, cwdOverride?) -> SessionManager
    header = readSessionHeader(path)        // reads at most the first 1MB
        // if the header is bigger than that, load the whole file instead
    cwd = cwdOverride or header.cwd or the process's cwd
    dir = sessionDir or the folder that holds path
    return new SessionManager(cwd, dir, path)   // → _setSessionFile(path)

fn _setSessionFile(file)
    if file does not exist:
        newSession(), but keep file as sessionFile      // created on the first message
        return
    entries = loadEntriesFromFile(file)
    if entries is empty:
        if the file is not empty:
            throw Error("Session file is not a valid pi session: <file>")
        newSession(), keep file, and write the header to it now
        return
    _loadEntries(entries)
    flushed = true                          // later entries are appended

#loadEntriesFromFile

Sourcesession-manager.ts › loadEntriesFromFile › parseSessionEntryLine

Reads the file line by line. A bad line is skipped, not fatal.

fn loadEntriesFromFile(path) -> FileEntry[]
    if path does not exist: return []
    read the file in 1MB chunks, keeping a UTF-8 character split across two chunks
        // why: (test: "opens session files larger than Node's max string length")
    for each line:
        parse it as JSON
        if the line is blank or not valid JSON: skip it
    if the first record is not a "session" header with a string id:
        return []                           // and leave the file as it is
    if the file did not end with "\n":
        append "\n" to the file
        // note: a crash during a write leaves a partial last line. It is skipped,
        //       and the next entry still starts on a line of its own.
    return entries

#_loadEntries

Sourcesession-manager.ts › SessionManager._loadEntries › migrateToCurrentVersion › migrateV1ToV2 › migrateV2ToV3

Takes the loaded entries and brings old files up to the current version.

fn _loadEntries(entries)
    header = the "session" entry
    if header:
        fileEntries = entries
        sessionId = header.id
        if migrateToCurrentVersion(fileEntries):
            _rewriteFile()                  // the one time Pi rewrites a whole file
    else:                                   // entries given to inMemory() without a header
        newSession()
        add entries after the new header
    _buildIndex()

fn migrateToCurrentVersion(entries) -> Bool
    version = header.version or 1
    if version >= 3: return false
    if version < 2:                         // v1 was a flat list
        give every entry a new id, and make the entry before it its parent
        turn compaction.firstKeptEntryIndex into firstKeptEntryId
    if version < 3:
        rename the message role "hookMessage" to "custom"
    set header.version
    return true

#_buildIndex

Sourcesession-manager.ts › SessionManager._buildIndex

Builds the lookup maps after a load. The leaf is the last line of the file.

fn _buildIndex()
    clear byId and the labels
    leafId = null
    for each entry in file order, skipping the header:
        byId[entry.id] = entry
        leafId = entry.id
        if entry is a label:
            set or clear labelsById[entry.targetId]     // the last label wins

So the leaf after a reload is the last entry that was written. A leaf move alone (branch, resetLeaf) is not saved. It becomes part of the file only when the next entry is appended below the new leaf.

#getBranch

Sourcesession-manager.ts › SessionManager.getBranch › buildSessionPath

The active branch: every entry from the root to the leaf.

fn getBranch(fromId = leafId) -> SessionEntry[]
    path = []
    entry = byId[fromId]
    while entry:
        path.add(entry)
        entry = byId[entry.parentId]        // stops at a root, or at a missing parent
    return path reversed                    // root first

The free function buildSessionPath, used by the projection, does the same walk with two differences. A null leaf gives an empty path. A leaf id that does not exist falls back to the last entry.

#branch, resetLeaf, branchWithSummary

Sourcesession-manager.ts › SessionManager.branch › SessionManager.resetLeaf › SessionManager.branchWithSummary

These move the leaf. Nothing in the file changes, except that branchWithSummary appends one entry.

fn branch(branchFromId)
    if byId has no branchFromId: throw Error("Entry <branchFromId> not found")
    leafId = branchFromId                   // the next entry is a child of it

fn resetLeaf()
    leafId = null                           // the next entry is a new root

fn branchWithSummary(branchFromId?, summary, details?, fromHook?, usage?) -> String
    if branchFromId is set and byId has no such entry: throw Error("Entry <id> not found")
    fromId = leafId or "root"               // the branch being left
    leafId = branchFromId
    _appendEntry({ type: "branch_summary", parentId: branchFromId, fromId, summary,
                   details, usage, fromHook, ... })
    return its id

/tree calls these through AgentSession.navigateTree (see the compaction page). If you pick one of your own messages, the leaf moves to that message's parent, and its text goes back into the editor. If you pick any other entry, the leaf moves to that entry.

#getTree

Sourcesession-manager.ts › SessionManager.getTree

The whole file as a tree, for /tree.

fn getTree() -> SessionTreeNode[]
    make a node for each entry, with its label and the label's timestamp
    for each entry:
        if entry.parentId is null, or is entry.id itself:
            add the node to roots
        else if the parent exists:
            add the node to the parent's children
        else:
            add the node to roots           // an orphan: its parent is missing
    sort every node's children by timestamp, oldest first
    return roots

#buildSessionProjection

Sourcesession-manager.ts › buildSessionProjection

Builds what the model sees from the active branch. AgentSession calls it before every request.

fn buildSessionProjection(entries, leafId, byId) -> SessionProjection
    path = buildSessionPath(entries, leafId)
    thinkingLevel, model = getSessionContextSettings(path)
    selected = buildContextEntries(entries, leafId)
    edits = {}
    for each context_edit in selected:
        edits[edit.targetId] = edit         // a later edit replaces an earlier one
    for each entry, at index i, in selected:
        if entry is a compaction and i > 0:
            messages = []
            // why: only the newest compaction, at index 0, adds a checkpoint and a summary
        else:
            messages = projectContextEntry(entry, edits[entry.id])
    return { entries: each entry with its messages,
             messages: all those messages in order, thinkingLevel, model }

A compaction can show up at i > 0 when a newer compaction keeps entries from before an older one. The older compaction is then inside the kept range.

#buildContextEntries

Sourcesession-manager.ts › buildContextEntries

Picks the entries that count, taking the newest compaction into account.

fn buildContextEntries(entries, leafId) -> SessionEntry[]
    path = buildSessionPath(entries, leafId)
    compaction = the last compaction entry on path
    if no compaction:
        return path
    result = [compaction]
    for each entry on path before compaction, starting at compaction.firstKeptEntryId:
        if entry is not a system message:
            result.add(entry)
            // why: the compaction saved the full system message at that point
    result.add(every entry on path after compaction)
    return result

A compaction that keeps nothing sets firstKeptEntryId to its own id. No entry before it matches, so only the summary and later entries are left.

#sessionEntryToContextMessages

Sourcesession-manager.ts › sessionEntryToContextMessages › projectContextEntry

What each entry type adds to the context, and how a context edit changes it.

fn sessionEntryToContextMessages(entry) -> AgentMessage[]
    match entry.type:
        "message":
            return [entry.message]          // missing content becomes "" or []
            // why: from the code: "old versions, forks, or hand-edited files can
            //      contain messages with null/missing content"
        "custom_message":
            return [createCustomMessage(customType, content, display, details, timestamp)]
        "branch_summary" with a summary:
            return [createBranchSummaryMessage(summary, fromId, timestamp)]
        "compaction":
            return [systemMessage, createCompactionSummaryMessage(summary, tokensBefore, timestamp)]
                   // without systemMessage if the entry has none (older files)
        otherwise:
            return []       // model_change, thinking_level_change, custom, label,
                            // session_info, usage, context_edit

fn projectContextEntry(entry, edit?) -> AgentMessage[]
    messages = sessionEntryToContextMessages(entry)
    if no edit: return messages
    if edit.replacement is null: return []  // the entry is left out
    return messages with content replaced by edit.replacement.content
        // a string for an assistant or tool result becomes one text block

The summary messages are not plain user messages yet. convertToLlm turns them into user messages with the summary in

tags, when the request is sent.

#getSessionContextSettings

Sourcesession-manager.ts › getSessionContextSettings

The model and thinking level come from the whole branch, not only from the part after a compaction.

fn getSessionContextSettings(path) -> { thinkingLevel, model }
    thinkingLevel = "off"
    model = null
    for each entry on path:
        match entry:
            thinking_level_change: thinkingLevel = entry.thinkingLevel
            model_change:          model = { entry.provider, entry.modelId }
            assistant message:     model = { message.provider, message.model }
    return { thinkingLevel, model }

#appendContextEdit

Sourcesession-manager.ts › SessionManager.appendContextEdit

Changes what one earlier entry adds to the context, without touching that entry. Used, for example, to hide a failed attempt after a context overflow.

fn appendContextEdit(targetId, replacement) -> String
    if replacement is not null and its content is not a string or an array:
        throw Error("Context edit replacement must be null or contain string/array content")
    if byId has no targetId: throw Error("Entry <targetId> not found")
    if targetId is not on getBranch(): throw Error("Entry <targetId> is not on the active branch")
    if the target is not a user, assistant, toolResult, or custom message:
        throw Error("Entry <targetId> does not contribute editable model content")
    turn a string replacement for an assistant or tool result into one text block
    _appendEntry({ type: "context_edit", targetId, replacement, ... })

An edit is on the branch like any other entry. Move the leaf back above the edit, and the target's original content is what the model sees again.

#appendCompaction

Sourcesession-manager.ts › SessionManager.appendCompaction

Saves a compaction. The compaction page covers how Pi writes the summary and picks firstKeptEntryId.

fn appendCompaction(summary, firstKeptEntryId?, tokensBefore, details?, fromHook?, usage?) -> String
    systemMessage = getCurrentSystemMessage(buildSessionProjection().messages)
        // the prompt and tools as they are now, replayed from every system message
    id = generateId(byId)
    _appendEntry({ type: "compaction", id, parentId: leafId, summary,
                   firstKeptEntryId: firstKeptEntryId or id,     // own id: keep nothing

#createBranchedSession

Sourcesession-manager.ts › SessionManager.createBranchedSession

Starts a new session file that holds one path of the old tree, from the root to leafId. /fork and /clone use it. This manager switches to the new file.

fn createBranchedSession(leafId) -> String?
    path = getBranch(leafId)
    if path is empty: throw Error("Entry <leafId> not found")
    kept = path without its label entries
    set each kept entry's parentId to the kept entry before it
        // why: from the code: "later entries can be children of labels; removing
        //      labels requires re-chaining the retained path to avoid orphaned subtrees"
    if a compaction's firstKeptEntryId is a removed label: point it at the next kept entry
    header = { new uuidv7 id, now, cwd, parentSession: the old file }
    labels = a new label entry at the end for each label on a kept entry
                                            // same text, same timestamp
    fileEntries = [header] + kept + labels
    switch sessionId and sessionFile to the new ones; _buildIndex()
    if not persist: return undefined
    if kept has a user or assistant message:
        write the new file now
    else:
        let _persist create it on the first message
    return the new file's path

The old file is not changed. Other branches of the old tree are not copied.

#AgentSessionRuntime.fork

Sourceagent-session-runtime.ts › AgentSessionRuntime.fork

The runtime behind /fork and /clone. It builds the new file, then replaces the running AgentSession with one on that file.

async fn fork(entryId, { position = "before" }) -> { cancelled, selectedText? }
    if @hook session_before_fork cancels: return { cancelled: true }
    entry = sessionManager.getEntry(entryId) or throw Error("Invalid entry ID for forking")
    if position == "at":                    // /clone: up to and including the leaf
        target = entry.id
    else:                                   // /fork: back to just before one of your messages
        if entry is not a user message: throw Error("Invalid entry ID for forking")
        target = entry.parentId
        selectedText = the message's text   // goes back into the editor
    if target is null:                      // forking the very first message
        manager = a new empty session with parentSession = the current file
    else:
        if the current file does not exist yet:
            throw Error("This session has not been saved yet. Send a message before cloning or forking it.")
        manager = SessionManager.open(current file)
        manager.createBranchedSession(target)
    stop the current runtime
    start a new runtime on manager          // emits session_start{reason: "fork"}
    return { cancelled: false, selectedText }

An in-memory session (--no-session) does the same on its current manager, with no files.

#forkFrom

Sourcesession-manager.ts › SessionManager.forkFrom

--fork at startup, or opening a session that belongs to another folder. Unlike createBranchedSession, it copies the whole tree.

static fn forkFrom(sourcePath, targetCwd, sessionDir?, options?) -> SessionManager
    entries = loadEntriesFromFile(sourcePath)
    if entries is empty: throw Error("Cannot fork: source session file is empty or invalid: <path>")
    if there is no header: throw Error("Cannot fork: source session has no header: <path>")
    dir = sessionDir or getDefaultSessionDir(targetCwd)
    header = { new id (or options.id), now, cwd: targetCwd, parentSession: sourcePath }
    write header to a new file in dir, with flag "wx"
    append every entry from the source, unchanged
    return a manager on the new file

#continueRecent

Sourcesession-manager.ts › SessionManager.continueRecent › findMostRecentSession

--continue: open the newest session for this folder, or start a new one.

static fn continueRecent(cwd, sessionDir?) -> SessionManager
    dir = sessionDir or getDefaultSessionDir(cwd)
    filterByCwd = dir is a custom folder shared by all projects
    file = findMostRecentSession(dir, cwd if filterByCwd)
    return a manager on file, or on a new session if there is none

fn findMostRecentSession(dir, cwd?) -> String?
    for each *.jsonl file in dir, newest modification time first:
        header = the file's header, or nothing if it can't be read
        if header and (no cwd given or header.cwd is cwd):
            return the file
    return null

"Newest" means the file that changed last. Every new entry is an append, so that is the session you used last.

#Rules

MUST     add every new entry as a child of the current leaf, then move the leaf to it
MUST NOT change or delete a line already in the file    // except a one-time migration rewrite
MUST NOT create a session file before the session has a user or assistant message
MUST     create new files with the "wx" flag, never overwriting an existing file
MUST     skip blank and malformed lines when loading, and keep the rest
MUST NOT change a non-empty file whose first record is not a session header
MUST     build the model's context from the active branch only, root to leaf
MUST     use only the newest compaction on the branch for the summary and checkpoint
MUST NOT send system messages from before that compaction
MUST     apply only the latest context edit for each target on the active branch
MUST NOT change the target entry of a context edit
MUST     take the model and thinking level from the whole branch, including entries before a compaction
MUST     record the source file as parentSession when forking or cloning
MUST NOT copy label entries into a fork as they were    // they are rebuilt at the end
SHOULD   show entries whose parent is missing as roots, not drop them

#Notes

Append-only is what makes the file safe to write. Saving an entry is one appendFileSync of one line. If Pi crashes in the middle, the worst case is a partial last line. The next load skips it and adds the missing "\n", so the session still opens with everything before it.

Labels and session names are entries in the tree too. appendLabelChange and appendSessionInfo add a child of the leaf and move the leaf, like a message. createBranchedSession treats labels apart for that reason.

The projection is built from scratch for every request, by walking the branch from the leaf to the root. AgentSession installs it in the Agent's prepareRequest, so the messages in a request always come from the entries. A compaction, a branch summary, or a context edit takes effect on the next request just by being on the branch.

Branch summaries record where you came from in fromId, but the summary's parentId is the point you moved to. That is why the summary is on the new branch and the model on that branch sees it.
